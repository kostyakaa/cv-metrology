# Проверка experimental на UC60 и GRBL

Цель испытания — определить, в какой части поля, на каких поверхностях и при какой длительности скана достигается ±0,10 мм отдельно по X, Y и Z. Команды ниже рассчитаны на PowerShell из корня проекта. Первая серия проводится с текущей оптикой; затем меняйте по одному условию. Сохраняйте неудачные серии и исходники.

## 1. Подготовка и контроль без движения

На компьютере с рабочей копией переключитесь на `experimental`. Для переноса на другой компьютер скопируйте предоставленный файл `experimental.bundle` в каталог рядом с клоном. В клоне с базовым коммитом dev `1fe4d21` выполните `git fetch ../experimental.bundle experimental`, затем `git switch -c experimental FETCH_HEAD` (если ветка ещё не создана). Все следующие команды выполняются в одном рабочем каталоге. Проверьте `git status -sb` и `git log -1 --oneline`.

```powershell
python -m pip install -r requirements.txt
python -m unittest discover -s tests -q
python scripts/mosaic_report.py mosaics/20261123-163106/fused
python z/measure_height.py --from-scan scans/scan_20261123-171208 --below 18 --analysis-out bench/replay-01
python z/check_region.py bench/replay-01/heights.npz --roi 286 184 384 38 --expected 9.85 10.00
```

Папка вывода должна быть новой. Архивная мозаика 16:31 должна сообщить `usable: False`, расхождение X около +4,657 мм и отсутствие принятых ID. Сохраните версии Python, OpenCV, NumPy и вывод тестов. Область в последней команде относится только к архивному скану П‑детали, координаты X,Y,W,H в пикселях исправленной карты 960×540.

Контрольный пересчёт архива на OpenCV 5.1.0: для указанной ROI верха медиана +10,155 мм, измерено 1102/14592 пикселей, p95 ошибки до ближайшей границы эталонного интервала 0,253 мм. Для ROI паза `319 354 296 36` при эталоне −12,65 мм медиана −12,083 мм, измерено 999/10656, встречаются положительные выбросы. Проверьте в кадре, какая доля окна действительно приходится на дно. Для области 68×47 мм с запасом 7 мм при шаге 0,5 мм и пороге согласия 0,35 мм у 10133/20295 ячеек есть измерение, у 2006 значения согласовались по нескольким опорам. Такая сетка годится для оценки покрытия. Проверять размер боковины 4,76 мм с допуском 0,10 мм нужно по исходным изображениям и независимым физическим граням.

## 2. Исходное состояние и проверка XY

На подвижном столе закрепите деталь и метки на общей оснастке. Для исходной серии используйте прежние метки ID0–3, зафиксируйте направление подвижной оси, положение головки, освещение и фокус. Начните с проверенного рабочего положения, ориентировочно 84 мм от оптического центра до стола. Механический зазор проверяют по ближайшей части головки. Инструмент и шпиндель выключены. На первой пробе камера должна видеть угловую метку, с доступным ходом для осевой проверки и возврата.

Следующий блок создаёт отдельный каталог запуска и рабочие копии геометрии. Файлы из calib сохраняются. Укажите имя вашей камеры, номер порта и фактически установленный профиль.

```powershell
$run = Join-Path 'bench' (Get-Date -Format 'yyyyMMdd-HHmmss')
New-Item -ItemType Directory -Path $run | Out-Null
Copy-Item calib/table_frame.json "$run/frame.json"
Copy-Item calib/table_plane.json "$run/plane.json"
$profile = 'calib/calib_cam0_1920x1080_pinhole.json'
$cameraArgs = @('--camera-name','UC60 Video','--port','COM4','--width','1920','--height','1080','--calib',$profile)
$geometryArgs = @('--frame-file',"$run/frame.json",'--plane-file',"$run/plane.json")
Start-Transcript -Path "$run/session.txt"
python scripts/scan_plane.py @cameraArgs @geometryArgs --preflight
python scripts/scan_plane.py @cameraArgs @geometryArgs --trial
```

В пробе нажмите `c → k → p`. Сверьте физические направления X/Y и возврат к той же метке. Для первой аппаратной проверки ожидаются 5 остановок и 4 подтверждённых участка движения. Выйдите через `q`. Для полного поля запустите рабочий режим:

```powershell
python scripts/scan_plane.py @cameraArgs @geometryArgs
```

Выполните `c → k → r → t → p`. На иной конфигурации меток сначала проверьте их реальную раскладку и доступный ход. Запишите номер сеанса из консоли. В мозаике дважды выберите разные точки после увеличения. Масштаб окна должен сохраниться. Команда `g` доступна в привязанном сеансе с завершённым маршрутом, замыканием в пределах 0,5 мм и минимум тремя различными принятыми метками. Этот порог выявляет грубый срыв привязки. Для проверки ±0,10 мм измерьте независимые точки у центра и четырёх краёв, по три повтора с разным направлением подхода. Запишите ошибки со знаком отдельно по X и Y до и после доводки.

Выполните `python scripts/mosaic_report.py mosaics/<номер>/fused`, подставив реальный номер. В JSON смотрите отдельно `closure_command_mm` (возврат относительно раскладки), `return_to_start_mm` (возврат относительно начального наблюдения), принятые ID, невязки отложенных пар, длительности интервалов движения и причины потери потока.

## 3. Плоскость, карта объекта и паз

Положите П‑деталь, снимите свежий обзор этой установки. На мозаике выберите первую вершину прямоугольника детали и нажмите `a`, затем противоположную и снова `a`. Появятся размеры и выбранный центр. Нажмите `g`, подтвердите наведение, затем `q → b`. Прямоугольник ориентирован по командным X/Y. У поднятого объекта проекция на плоскую мозаику смещается, поэтому для первого прогона оставьте запас по контуру. Можно задать размеры заранее:

```powershell
python scripts/scan_plane.py @cameraArgs @geometryArgs --area-mm 68 47 --area-margin 7 --below 18
```

При таком запуске сначала подведите центр камеры к центру детали. План до подтверждения покажет охват и число остановок. Для сложного контура площадь можно разделить на несколько участков. Программа проверяет геометрическую видимость с шагом примерно 2 мм, на крайних уровнях высоты, и добавляет остановки при недостатке ракурсов. Лимит текущего планировщика области — 49 остановок. Видимость текстуры и закрытие дна стенками проверяются по результату.

Кликните по поверхности стола, перемычке и обеим ножкам. Для паза выбирайте заранее отмеченный участок дна вдоль прорези. Повторите трижды со свежей съёмкой. Для каждого нового положения выберите свои ROI. При необходимости задайте одну или несколько опорных площадок параметром `--table-roi X Y W H` в координатах половинной исправленной карты. Нужно достаточно текстурированных точек стола, распределённых по полю. При недостатке данных отчёт укажет переход к исходной плоскости. Сравнивайте серии с одинаковой базой высот.

- `heights.npz` содержит подписанные мм и отдельные маски measured, filled и glare. `clicks.jsonl` сохраняет и отклонённые попытки.
- `area/area.npz` содержит XY-сетку нескольких опор, высоту, число карт, размах Z и маску confirmed. В coverage.png зелёные ячейки согласованы, серые имеют одну оценку, оранжевые показывают конфликт, тёмные пусты. Начальный порог согласия 0,35 мм служит для диагностики. Показатель perimeter относится к полосе по периметру выбранного прямоугольника.
- Для сравнения без движения повторите `python z/area_height.py scans/<сеанс> --area-mm 68 47 --area-margin 7 --below 18 --agree-mm 0.10 --out bench/area-010`. Отдельно пересчитайте `--below 3` и `--below 18`, сравните покрытие и ошибку относительно −12,65 мм. Эталон глубины используйте только для оценки результата.
- Для проверки связи камеры и станка закрепите несколько вспомогательных ArUco DICT_4X4_50 с разными ID 4–49 на оснастке. Измерьте высоту поверхности рисунка относительно исходной плоскости guess. Если рисунки лежат в плоскости угловых меток и guess задана ими, используйте `--pose-tag-height 0`. На тех же сырых снимках сравните расчёты без коррекции и с этим параметром. Параметр применяется ко всем видимым ID 4–49, поэтому они должны быть на одной известной высоте и двигаться вместе с деталью. В `pose_fit` записаны исходные и проверочные невязки, поправки, признак применения. При слабой или несвязной привязке используются исходные показания GRBL. Для отключения в повторном расчёте сохранённой серии используйте `--no-pose-refinement`.

При пересвете повторите ту же траекторию с рассеянным боковым светом, фиксированной выдержкой и прежним фокусом. Сравните доли пересвета, измеренных ячеек и ошибки на одной ROI. Для блестящей поверхности можно отдельно испытать скрещённые поляризаторы на источнике и перед объективом. Для однотонного дна добавьте матовую текстуру только на контрольном образце и учтите толщину покрытия. Если дно закрыто стенкой во всех доступных ракурсах, его высоту в этой области оставляют неизвестной.

Для сравнения выбора ракурсов на архиве снимите две карты в новых папках. Вторая команда берёт плоскость стола из первой карты и сохраняет ту же сетку.

```powershell
python z/area_height.py scans/scan_20261123-171208 --area-mm 68 47 --area-margin 7 --below 18 --out bench/all
python z/area_height.py scans/scan_20261123-171208 --area-mm 68 47 --area-margin 7 --below 18 --map-views 8 --view-selection nearest --datum-from bench/all/area.json --out bench/nearest
python z/fill_area.py scans/scan_20261123-171208 <outlines.json> bench/nearest bench/all bench/surfaces
```

Замените `<outlines.json>` путём к JSON с контурами верхних площадок на исправленном опорном кадре половинного разрешения. Формат использует индекс `frame` и массив `regions`. В каждой области указываются `name`, `polygon` с координатами пикселей, `fill` и контрольный интервал `expected_mm`. Для области с `fill: false` задайте `evaluation_z_mm` для проекции контура на сетку, например глубину контролируемой прорези. В результате `surfaces.npz` хранит исходную и достроенную высоты и маски. `regions.json` содержит проверку плоскостей и статистику измерений без достройки.

Для проверки робастного объединения повторите второй расчёт с `--fusion robust --out bench/robust` в новой папке. Сохранённый `area.npz` содержит `layer_height_mm`, `layer_score` и `reference_indices` по опорным картам. `baseline_height_mm` и `baseline_confirmed` воспроизводят прежний метод на тех же оценках. В `confirmation_method` значение 1 соответствует прежней проверке размаха, 2 — строгому большинству, 3 — проверке перепроекцией. Ноль означает отсутствие подтверждения. Поле `confirmed_height_mm` оставляет только подтверждённые значения. Маски `single` и `conflict` сохраняют оставшиеся одиночные и противоречивые ячейки.

## 4. Новая калибровка оптики

Проверьте физический шаг рисунка по двум осям на длинном отрезке и высоту его печатной поверхности над столом (+9,10 мм). В следующей команде номер камеры 0 — пример; проверьте индекс UC60. На плоской неподвижной доске выполните автоматическую XY-сетку клавишей `g` после проверки свободного места для указанного диапазона. Затем сделайте 8–12 дополнительных снимков клавишей `c` с наклонами доски в разные стороны и с углами рисунка у границ кадра. Нажмите `q` для расчёта.

```powershell
python scripts/calibrate_distortion.py --camera 0 --width 1920 --height 1080 --focus 185 --grbl COM4 --board 10mm --board-above-table 9.1
```

185 — значение привода фокусировки в существующем профиле UC60. Для выбора другого значения сравните резкость меток в центре и по углам, на столе и на верхней поверхности при рабочей высоте головки. Зафиксируйте выбранное значение до съёмки доски. Рабочую дистанцию выбирайте по охвату детали с запасом, чёткости интересующего диапазона глубин и ошибке независимых контрольных ступеней. 84 мм — исходная дистанция архивного скана, универсальной установки в миллиметрах нет.

Запишите напечатанные пути к JSON профиля и исходным снимкам. Повторите на тех же снимках с `--from-dir calib/<папка-кадров> --rational --board-above-table 9.1`. Сравните p95_board_mm отдельно по всему полю и краям, устойчивость фокусного, ошибку по независимому контрольному расстоянию. Профили по умолчанию разделены по режиму, фокусу и времени. Явное `--calib` при калибровке указывает файл для записи. Выбирайте новый путь. Значение 9,10 используется для расстояния до стола в метрическом проходе плоской доски. Наклонные позы имеют собственные внешние параметры.

Для проверки нового профиля замените `$profile`, заново создайте `$cameraArgs`, начните рабочий режим и повторите `c → k → r → t` с копиями геометрии. Preflight новой геометрии выполняйте после её записи. Для другого положения головки используйте отдельные файлы плоскости, распознаваемый физический отсчёт `--head-z-mm`, повторную привязку и обмер плоскости. Для другого фокуса или режима камеры сделайте отдельный профиль. На архивной серии из 37 поз OpenCV 5.1.0 дал p95 по краям 0,232 мм для обычной модели и 0,185 мм для rational. Обе оценки выше цели 0,10 мм. Сравните их с новой съёмкой до выбора модели.

## 5. Моторизованная Z и проба по резкости

Обычная клавиша `b` снимает при постоянной Z. Клавиша `j` запускает отдельную серию подъёма и возврата. Клавиша `z` сохраняет прежнее назначение установки рабочего нуля. Перед первой серией независимо проверьте знак подъёма головки, реальный ход Z индикатором и диапазон свободного перемещения в текущих координатах статуса GRBL при данном XY. Настройки другой оси для этого не подходят. Учтите крепёж и высоту самой детали. После сброса контроллера сверьте отсчёт заново.

В PowerShell введите проверенные на установке значения. При `j` программа напечатает систему координат, фактический старт и обе конечные позиции до подтверждения. Диапазон начинается в текущей позиции и идёт в сторону подъёма. Например, размах 1 мм и шаг 0,25 мм дают пять позиций для короткой пробы.

```powershell
$zLow = Read-Host 'Нижняя численная граница Z в координатах GRBL'
$zHigh = Read-Host 'Верхняя численная граница Z в координатах GRBL'
$zUp = Read-Host 'Знак физического подъёма: 1 или -1'
python scripts/scan_plane.py @cameraArgs @geometryArgs --focus-z-span 1 --focus-z-step 0.25 --z-feed 30 --z-up-sign $zUp --z-limits $zLow $zHigh
```

Поставьте головку в начальную точку, подключитесь `c`, наведите центральный участок на матовую текстуру и нажмите `j`. После успешной серии проверьте фактический возврат индикатором. При Esc или сбое серия остаётся на месте остановки, записывается частичный focus.json, измерительный процесс завершается. Убедитесь в положении головки до следующего запуска.

Для проверки чувствительности используйте ту же текстурированную мишень, затем добавьте измеренную прокладку 0,10 мм **в том же сеансе GRBL** и повторите `j`. Подберите старт и интервал так, чтобы по обе стороны пика было несколько измерений. Шаг 0,05–0,10 мм вокруг максимума — исходная проба для проверки чувствительности. При широкой или крайней вершине будет возвращён отказ. Простое уменьшение шага требуемую точность не гарантирует.

Для доски и детали используйте диапазон, охватывающий оба максимума с запасом, либо предварительно определите их положения короткими пробами. Широкий проход выполняйте только внутри проверенного диапазона. Центральное окно 97×97 px должно оставаться на одной физической площадке. Возможен боковой уход при ходе Z; проверьте его по сохранённым ROI. Сравнение двух завершённых серий из одного подключения:

```powershell
python scripts/focus_height.py scans/<focus-стол> scans/<focus-деталь>
```

Начните с пяти повторов перепада 0,10 мм и ступени +9,10 мм. Для П‑детали измерьте перемычку и каждую ножку. Для тёмного дна сначала проверьте видимость с текущего положения. Метод выдаёт высоту центральной площадки; для плотной карты применяйте XY-проход и многоопорную реконструкцию.

Для сравнения разрешений сначала проведите три одинаковых прохода в 1920×1080, затем три в другом реально поддерживаемом режиме. Сохраните ту же рабочую дистанцию, освещение и набор контрольных точек. Запишите фактический размер кадра, кодек, интервалы приёма кадров на остановках и в движении, время полного прохода. При низком FPS проверьте число валидных отрезков оптического слежения. Если оно падает, уменьшите подачу и повторите. Выигрыш оценивайте по ошибке на деталях и доле измеренного контура за время полного скана.

## 6. Что вернуть с испытаний

Завершите `Stop-Transcript`. На первом проходе достаточно одной хорошей серии и одной проблемной. Для разбора нужны:

1. Вывод `git log -1 --oneline`, версия OpenCV, команды запуска, transcript, фактические камера/формат/фокус, условия света, положение головки, знак и измеренный ход Z. Для проверки FPS приложите интервалы из captures и preview_dt, по возможности укажите выдержку.
2. JSON выбранной калибровки, mode.json, при проблеме с краями — исходные кадры доски. Приложите рабочие frame.json и plane.json.
