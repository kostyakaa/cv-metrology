# Первый запуск на установке

Команды выполняются в PowerShell из корня проекта. Первый прогон рассчитан на прежнюю установку с UC60, разрешением 1920×1080, портом COM4 и четырьмя метками ArUco ID0–3. Фокус 185 относится к поставляемому профилю этой камеры. Программа выставляет ручной фокус из выбранного профиля и проверяет показание драйвера.

## Меню и сохранённые установки

Из корня проекта запустите

```powershell
python scripts/metrology.py
```

Выберите действие стрелками и нажмите Enter или щёлкните по строке. Ctrl+K переводит фокус в поиск, Esc возвращает назад, F3 показывает журнал, Ctrl+Q завершает терминал. Камера, мозаика и карта высот открываются в отдельных окнах. Во время съёмки нажимайте клавиши в окне камеры. Вывод скриптов и результат выполнения видны в журнале. Если обновляетесь с прежней версии, выполните `python -m pip install -r requirements.txt`.

Команда «Открыть рабочую сессию» открывает камеру с параметрами выбранной установки. При первом запуске профиль `uc60` получает копии текущей оптики, раскладки и плоскости из `calib`. Меню хранит их в `calib/setups/uc60`. Команды «Создать установку», «Выбрать установку» и «Настроить установку» управляют профилями. Выбранная установка запоминается. Профиль оптики копируется целиком. Для другой оснастки заведите отдельную установку, укажите расстояния между центрами меток и выполните первый обход вручную.

При смене детали на той же оснастке, с теми же метками, оптикой и положением головки, достаточно `c → k` на видимой угловой метке, затем `b` в центре новой детали. В уже открытом сеансе после смены одной детали достаточно `b`. Команда «Наведение по мозаике» позволяет снова использовать совместимую сохранённую мозаику. Снимите новое поле, если на мозаике нужна новая деталь. Если перенесли саму оснастку относительно траектории, проверьте рабочую зону и положение меток. При перестановке меток повторите `r → t`. При изменении только высоты головки обновите её отсчёт в настройках и выполните `t`. При смене фокуса, разрешения или крепления камеры проверьте оптический профиль.

### Полный цикл

Команда «Полный цикл по четырём меткам» или аргумент `--auto` запускает `k → r → t → p` после `c` на видимой угловой метке. Требуется сохранённая раскладка. Один общий запрос подтверждает весь маршрут. Аргумент `--yes` пропускает этот запрос. Клавиша `e` запускает такой же цикл вручную в открытом окне камеры. Esc останавливает текущий ход. При несовпадении настроек, нарушении проверки направления или замыкания следующая стадия не запускается. После цикла ход по клику снова подтверждается отдельно.

```powershell
python scripts/scan_plane.py --camera-name "UC60 Video" --port COM4 --width 1920 --height 1080 --calib calib/calib_cam0_1920x1080_pinhole.json --auto --yes
```

Прямая команда использует файлы в `calib`. Меню использует файлы выбранной установки. `k` проверяет масштаб относительно настроек `$100/$101`, записанных в оптическом профиле, и останавливает работу при смене числа шагов на мм.

### Проверка масштаба

На архивной серии из 37 кадров повторный расчёт дал практически одинаковый ход по линейке доски для обычной и рациональной модели. Около 0,9935 мм по X и 0,9946 мм по Y на командный мм. P95 ошибки на отложенных углах по краям кадра составил 0,232 мм для pinhole и 0,185 мм для rational. Это проверка камеры на рисунке доски. Для цели ±0,10 мм проверьте реальные длины и высоты на независимых эталонах по полю.

При новом замере измерьте шаг сразу по нескольким клеткам вдоль обеих осей. Если шаг одинаков, передайте измеренное среднее через `--square-mm` или поле шага в «Калибровка по ChArUco». При разном масштабе печати по X и Y лучше применить другую мишень. Сравните обе модели на той же серии с наклонами и углами у краёв. После выбора нового профиля в «Настроить установку» измерьте плоскость клавишей `t`. Режим `--preflight` проверяет совместимость файлов и показывает масштаб, записанный в профиле.

## Подготовка

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -q
```

Если PowerShell с CP1251 выдаёт `UnicodeEncodeError` при перенаправлении вывода или вызове `--help`, установите в этой сессии `$env:PYTHONIOENCODING='utf-8'`.

Замените номер версии Python в первой команде, если на ПК установлен другой поддерживаемый Python. Точное имя камеры и порт можно узнать без открытия видеопотока и порта.

```powershell
.\.venv\Scripts\python.exe -c "from pygrabber.dshow_graph import FilterGraph; print(FilterGraph().get_input_devices())"
.\.venv\Scripts\python.exe -m serial.tools.list_ports -v
```

Установите головку в рабочее положение, использованное для файлов геометрии. В архивном скане оптическая дистанция до стола была около 84 мм. Проверьте зазор по ближайшей к детали части головки на всём планируемом ходе. Закрепите деталь и метки на одной оснастке, чтобы они перемещались вместе со столом. Выключите шпиндель, выставьте равномерный свет и оставьте свободным ход у угловой метки. Для локальной пробы нужен ход в пределах ±8 мм от положения подключения.

## 1. Проверка файлов и короткий ход

```powershell
$py = '.\.venv\Scripts\python.exe'
$session = 'bench/hardware-01'
$setup = @{
    Python = $py
    RunDir = $session
    CameraName = 'UC60 Video'
    Port = 'COM4'
    Profile = 'calib/calib_cam0_1920x1080_pinhole.json'
    Width = 1920
    Height = 1080
}
.\scripts\run_metrology.ps1 @setup -Stage Check
Start-Transcript -Path "$session/session.txt"
.\scripts\run_metrology.ps1 @setup -Stage Trial
```

`Check` проверяет список устройств и совместимость файлов. При создании сеанса копирует раскладку и плоскость в `$session`. Файлы из `calib` сохраняются. У нового ПК имя камеры и номер COM могут отличаться. Значения GRBL $3, $100, $101 берутся из файлов и сравниваются при подключении. Если значения расходятся, выясните причину и обновите калибровку для реальной установки.

В окне пробы подведите камеру к одной метке ID0–3. Нажмите `c → k → p`, сверяя направление изображения при движении каждой оси и проверяя возврат к метке. Подтвердите движения в интерфейсе. Завершите клавишей `q`. Если ход вышел в неверную сторону или возврат расходится с физической проверкой, остановитесь на этом этапе.

## 2. Съёмка П-детали

```powershell
.\scripts\run_metrology.ps1 @setup -Stage Capture -AreaX 68 -AreaY 47 -Margin 7 -Below 18
```

1. На угловой метке нажмите `c → k`. При необходимости заново обойдите метки `r` и измерьте плоскость меток `t`. Команды запишут рабочие копии сеанса.
2. Клавишами WASD подведите камеру к центру прямоугольника детали. Клавиши `1 / 2 / 3` меняют шаг ручного перемещения.
3. Нажмите `b`. Проверьте охват, число остановок и пределы движения перед подтверждением. Сетка начинается с 5×5. Планировщик может уменьшить командный шаг 16 мм или добавить точки по области. При низком охвате центрируйте область заново. Шаг сетки итоговой карты составляет 0,5 мм.
4. Дождитесь сообщения о сохранении `scans/scan_...`, запишите путь и завершите `q`. В каталоге будут исходные кадры, фактические XYZ, сведения о режиме камеры и параметры съёмки. Для первой серии держите Z головки, фокус, разрешение и свет постоянными.

## 3. Пересчёт той же серии

Подставьте путь, который напечатала съёмка. Используйте те же размеры области, запас и глубину. Каталог результатов должен быть новым.

```powershell
$scan = Read-Host 'Путь к папке scans/scan_...'
$out = "$session/analysis-01"
.\scripts\run_metrology.ps1 -Stage Analyze -RunDir $out -Python $py -Scan $scan -AreaX 68 -AreaY 47 -Margin 7 -Below 18
& $py z/view_height_map.py "$out/stereo-original/area.npz"
Stop-Transcript
```

- `baseline/area.json` описывает общий ноль Z. Проверьте `table_reference` и высоты на открытом столе. Плоскость меток может отличаться по высоте от стола. Перед сравнением Z паза с −12,65 мм проверьте поверхность, принятую за ноль.
- `stereo-original` содержит стереокарту с сохранённым базисом. `axes.json` показывает остатки и решение по поправке на новом скане. Если `accepted: true`, дополнительно появится `stereo-corrected`. Обе карты используют один ноль и входные кадры.
- В каждой папке стерео есть `area.npz`, `area.json`, `height.png` и `height_3d.png`. Значение `confirmed` означает согласие независимых пар. Для проверки ±0,10 мм выберите открытый стол, перемычку, обе ножки и видимое дно прорези, отдельно запишите фактические ошибки и долю подтверждённых ячеек. Эталонные размеры не входят в расчёт.

## Если поменялись оптика, высота головки или оснастка

При смене разрешения или фокуса создайте отдельный профиль камеры. При смене Z головки запишите воспроизводимое значение и передавайте его как `HeadZmm` в `$setup`. Сначала измерьте новую плоскость `t` при этой высоте. При изменении раскладки повторите `r` и `t`. Подготовьте новую геометрию по разделам 2 и 4 руководства [EXPERIMENTAL_TESTING.md](EXPERIMENTAL_TESTING.md). После записи передайте её рабочие файлы через `FrameSource` и `PlaneSource` в новом сеансе. Если число пикселей увеличено, отдельно запишите реальный FPS и интервалы кадров из `scan.json`. Сначала повторите тот же маршрут и сравните точность и покрытие.

Для разбора пришлите `session.txt`, папку `scans/scan_...` с PNG и `scan.json`, обе `area.json`, `axes.json` и список контрольных площадок с эталонными высотами. Укажите, какая ось перемещала стол, и была ли сохранена высота головки.

## 4. Обычная работа с мозаикой и картой Z

Для полного прохода используйте обычный запуск `scan_plane.py`. Скопированная геометрия сеанса лежит в `$session`. Если перед этим измеряли `r` и `t` в режиме Capture, этот запуск возьмёт записанные там файлы.

```powershell
& $py scripts/scan_plane.py --camera-name "UC60 Video" --width 1920 --height 1080 --calib calib/calib_cam0_1920x1080_pinhole.json --port COM4 --frame-file "$session/frame.json" --plane-file "$session/plane.json" --area-mm 68 47 --area-margin 7 --below 18
```

1. На видимой угловой метке нажмите `c`, затем `k`. При новой раскладке пройдите `r`. Для обхода с нуля задайте реальные расстояния между центрами меток через --span-x и --span-y. Для новой геометрии или высоты камеры измерьте плоскость меток клавишей `t`. При заданном `HeadZmm` передайте то же значение через `--head-z-mm`.
2. `p` снимает всю плоскость и собирает мозаику в `mosaics/<сеанс>/fused`. `v` открывает её повторно. Колесо масштабирует, клик выбирает XY, `g` запрашивает подтверждение хода. После остановки возможна доводка по камере при надёжном совпадении с мозаикой.
3. Обведите деталь на мозаике. Для каждой вершины кликните и нажмите `o`, последнюю вершину можно убрать клавишей `u`. После трёх или более вершин нажмите Enter. Для прямоугольной области достаточно отметить два противоположных угла через клик и `a`. Жёлтая рамка показывает габариты, голубая включает запас. Скан охватывает весь прямоугольник, включая выемки детали. Нажмите `g` для хода к центру, `q` для выхода из мозаики, затем `b` для локального скана.
4. Обычный `b` сохраняет кадры, строит центральную карту `heights.npz` и при заданной области многоопорную `area/area.npz`. Запуск с `--capture-only` или через `-Stage Capture` заканчивает работу с серией после сохранения кадров. Для карты по независимым стереопарам используйте `-Stage Analyze`.

Навигация по сохранённой мозаике работает через `--open ПАПКА` после повторной привязки `c → k → h`. Для одного просмотра используйте `--view ПАПКА`. Незавершённый проход, отсутствие допустимого замыкания, менее трёх опорных меток или несовпадение профиля/положения Z переводят мозаику в режим просмотра. Порог замыкания 0,5 командного мм служит для грубой проверки привязки.

Пересборка мозаики из сохранённых кадров и отчёт выполняются офлайн.

```powershell
$mosaic = 'mosaics/20261123-163106'
& $py scripts/rebuild_mosaic.py $mosaic --out "$mosaic/fused-review"
& $py scripts/mosaic_report.py "$mosaic/fused-review"
& $py scripts/scan_plane.py --view "$mosaic/fused-review"
```

Для этой архивной мозаики пересборка дала покрытие 100% и p95 невязки на 21 отложенной паре 0,054 мм после совмещения против 0,342 мм по GRBL. Отчёт оставил её в режиме просмотра. Замыкание около 4,66 командного мм, опорные метки отсутствуют. Для наведения нужен новый проход, удовлетворяющий проверке привязки.

## 5. Какой результат строить

| Результат | Чем строить | Что смотреть |
|---|---|---|
| Мозаика и наведение XY | `p` или `scripts/rebuild_mosaic.py` | `fused/mosaic.json`, отчёт о замыкании, метках и оптических смещениях |
| Центральная карта Z, измерение кликом | Обычный `b` или `z/measure_height.py --from-scan` | `heights.npz`, `heights.png`, `result.json`. Прямые оценки и плоская достройка имеют отдельные маски |
| Карта Z в общей сетке XY | Обычный `b` с областью или `z/area_height.py` | `area.npz`, `area.json`, `coverage.png`. Годится для сравнения опорных кадров и настройки покрытия |
| Измерения по независимым стереопарам | `-Stage Analyze` | `stereo-original`, при принятом повороте также `stereo-corrected`. Смотрите `height.png`, `height_3d.png` и `area.json` |
| Вращаемая 3D-карта и поверхность | `z/view_height_map.py`, `z/plot_3d_npz.py` | Открывают готовый `area.npz` или `surfaces.npz`. Для оценки геометрии начните с `--mode confirmed` |
| Достройка плоской размеченной грани | `z/fill_area.py` | `surfaces.npz`, `regions.json`. Подтверждённые измерения служат опорами, достройка идёт отдельным слоем |
| STL для визуализации формы | `z/make_model.py` | Снова обрабатывает исходный скан старым способом и строит 2,5D-модель с заполнением и стенками до стола |

Команды для просмотра результатов и повторного расчёта центральной карты выполняются без оборудования. Для `$map` можно выбрать `stereo-corrected/area.npz`, если поправка прошла проверку, и сравнить с исходным вариантом.

```powershell
$map = "$out/stereo-original/area.npz"
& $py z/view_height_map.py $map
& $py z/plot_3d_npz.py $map --mode confirmed --show --out "$out/mesh.png"
& $py z/measure_height.py --from-scan $scan --below 18 --no-fill --analysis-out "$out/central"
& $py z/make_model.py $scan --out "$out/stl"
```

Размер ячейки 0,5 мм задаёт дискретизацию XY-карты. Порог согласия 0,35 мм определяет приём наблюдений. Для проверки точности ±0,10 мм нужны независимые эталоны и повторы.

### Что изменилось относительно dev

- В `dev` основной результат Z строился из одного опорного кадра. Перебор глубин с ZNCC, отсев неоднозначных пиков, уточнение кликов и фильтры по локальной поддержке сохранились. На архиве `scan_20261123-171208` в `dev` измерилось 15,2% опорного кадра, 44,2% дала плоская достройка. На участке перемычки достройка дала 0,068 мм при медиане измеренных точек 10,183 мм. Эти проценты относятся к пикселям кадра.
- `area_height.py` объединяет карты из нескольких опорных кадров на общей сетке XY. По умолчанию выбирает пять опор и подтверждает ячейку, когда есть две или больше оценок с размахом до 0,35 мм. Режим `--fusion robust` также проверяет строгое большинство и перепроекцию. Совпадения из производных карт уже не могут подтвердить гипотезу меньшинства при конфликтующих прямых оценках. Опорные карты могут использовать общие исходные кадры.
- `network_height.py` проверяет соответствие на исходных изображениях пары, триангулирует и отбрасывает наблюдения с признаками перекрытия. Для подтверждения нужны три пары без общих кадров, согласие в пределах 0,35 мм и строгое большинство. `fit_stereo_axes.py` оценивает общий поворот базиса по SIFT и проверяет его на отложенных парах X, Y и диагоналей. Поправка действует только при пересчёте этого скана. На архиве медиана эпиполярного остатка упала с 0,902 до 0,358 px. Оценка глубины дна по-прежнему часто отсутствует.
- Для однотонной плоской грани появился `fill_area.py`. Он использует контуры на исправленном опорном кадре половинного размера и проверяет плоскость по подтверждённым опорам. Области с `fill: false` исключаются из достройки. Разметка П-детали подходит только к архивному кадру. Гладкая поверхность без опор и геометрически скрытое дно могут остаться пустыми.
- Калибратор добавил проверку на отложенных позах и углах, включая край кадра. Сеансы записывают профиль, ручной фокус, положение головки, координаты XYZ на остановках и интервалы кадров. `j` запускает отдельную моторизованную пробу по резкости. Для неё требуются проверенный знак подъёма и границы хода Z. Проба меряет центральную площадку, а обычный `b` работает при постоянной Z. Порядок проб описан в [EXPERIMENTAL_TESTING.md](EXPERIMENTAL_TESTING.md).

- В центральной карте бикубическая интерполяция заменила билинейную при сопоставлении. Измерение кликом учитывает маски видимости и проверяет, сколько ракурсов поддерживает найденный пик. SOR по k соседям по-прежнему доступен в `plot_3d.py` через `--sor-k` и выключен по умолчанию. В `network_height.py` выбросы отсекаются по согласованности пар.
- В XY добавлены проверка возврата к исходному наблюдению метки, проверка совместимости мозаики с профилем и Z, поправка локального масштаба в преобразовании клика и интервалы кадров движения в отчёте. Смешивание освещения и доводка по кадру уже были в dev.
- Вспомогательные ArUco ID4–49 на одной известной высоте позволяют уточнить относительные XY-позы в центральной и многоопорной реконструкциях. Параметр `--pose-tag-height` задаётся относительно плоскости `guess`. В отчёте `pose_fit` проверяйте `applied` и остатки на отложенных связях. Поправка базиса `fit_stereo_axes.py` для сетки стереопар подбирается отдельно.
- `pair_height.py` и `epipolar_height.py` служат для диагностики попарного поиска и прямого эпиполярного стерео. `audit_tracks.py` сравнивает треки по исходным изображениям. Для обычного запуска и просмотра достаточно `Analyze` и готовых карт.
